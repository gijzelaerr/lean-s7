# lean-s7 0.3.0 (candidate)

Experimental classic S7comm release. **Not PLC-qualified; do not use on production
equipment.** All supported-profile limitations of 0.1.0, 0.1.1 and 0.2.0 remain. This is a
candidate: it is not tagged or published until the repository owner approves the version
and tag, and its exact-revision CI passes.

## Library

Three behaviour changes since 0.2.0, each in its own merged change:

- **USER_DATA follow-up requests** of every group now send parameter method `0x12`. SZL
  follow-ups already did; block-list follow-ups sent the initial request's `0x11`. Real
  S7-300 captures and the native Snap7 client both send `0x12` (#49,
  [the evidence](../../reports/userdata-continuation-method-2026-10-08.md)). This is a
  wire change; conformance corpus 1.1.0 carries the corrected vectors.
- **Counter and timer transfers that need more than one request are rejected** before any
  IO (`MultiValidation.readFits`, `MultiValidation.writeFits`; #52). The chunk-advance step
  for these areas is unresolved (gate H1): the native Snap7 client, python-snap7 and
  lean-s7 disagree on it, so a longer transfer could read or write the wrong elements.
  `readFits_single_request` and `writeFits_single_request` prove that an accepted transfer
  is planned as exactly one request.
- **`Client.serialized`** now runs on a pure ticket model of its serialization gate
  (`Correlation.Gate`), and checks at run time that a ticket starts in order (#46). The
  queue order is proved on the model.

Everything else is new proofs. **Every decoder in the inventory now has a canonical-form
theorem** (or a proved leniency or characterisation, for the few that are lossy): the
classic S7 protocol path, USER_DATA responses, the PLC clock, the PDU reference, the COTP
disconnect request, STRING and WSTRING, and the force table (#62–#65,
[the plan and results](../plans/canonical-decoding.md)). Downstream, lean-s7commplus builds
its own canonical-form proofs on the cursor and `ByteArray.extract` lemmas these added.

1,743 theorems are audited by `lake exe lean-s7-axioms` (no `sorryAx`, no axioms beyond
`propext`, `Classical.choice` and `Quot.sound`); every theorem name the docs cite must
exist.

## Evidence added since 0.2.0

- The request encoders are checked against the recorded requests of the official native
  Snap7 client (#50), and its chunk sequences and parameter sweep are recorded (#51).
- The pinned native Snap7 server's SZL, block, clock, password and CPU-control services are
  exercised (#55); the native interop check accepts its Sunday weekday 0 (#71).
- A real S7-300 list-blocks-of-type follow-up request is pinned as a regression vector (#56).
- python-snap7 3.3.1 and 3.4.0 are reviewed against the conformance corpus and replay the
  real captures (#66, #69, #70); the python-snap7 consumer runs against both 3.0.0 and
  3.4.0 in CI.
- CI also runs on Windows, as an informational job (#57; an intermittent crash on the
  hosted runner is tracked in #58). The real-capture replay runs weekly (#45).
- Conformance corpus 1.1.1 only updates provenance for this version; its files are
  identical to 1.1.0.

## Use

Use the pinned Lean 4.33.1 toolchain and `v0.3.0` as the Lake dependency revision once
tagged. Python, Wireshark and native Snap7 remain test dependencies. No prebuilt binary
distribution is promised.

This is bounded evidence, not a full Client IO/scheduler-equivalence proof, and the
captures qualify only the conversations they contain. Physical controller and firmware
behavior beyond them, counter/timer addressing beyond one request, hard native socket
cancellation (no runtime primitive exists), exactly-once effects, multi-fragment uploads
and industrial safety remain unqualified. See `docs/RELEASE.md` and `docs/COMPLETENESS.md`.
