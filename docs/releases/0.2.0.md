# lean-s7 0.2.0

Experimental classic S7comm release. **Not PLC-qualified; do not use on production
equipment.** All supported-profile limitations of 0.1.0 and 0.1.1 remain.

## Library

- `Client` now calls a pure correlation core (`LeanS7.Correlation`) for PDU reference
  allocation and the stale-reply decision. Behavior is unchanged; this is the only
  production-code change to the client since 0.1.1 (about ten lines). Checked
  theorems (standard axioms only): a reply is delivered only to the awaited reference,
  stale replies spend exactly one unit of the allowance, the allowance is exceeded only
  after allowance+1 mismatching replies, and references are sequential across the 16-bit
  wrap and distinct within one 65,536 window.
- New checked decoder contracts: setup communication, DB write, upload start/fragment/end,
  download acknowledgement, PLC control, SZL (and the first USER_DATA fragment),
  COTP connection confirm and TLV parameters, and `decodeDbRead`. The decoder inventory in
  `docs/COMPLETENESS.md` names the theorem for every decoder.
- 1,388 theorems are audited by `lake exe lean-s7-axioms` (no `sorryAx`, no axioms beyond
  `propext`, `Classical.choice` and `Quot.sound`); every theorem name the docs cite must
  exist.

## Tools (not runtime dependencies, outside the library import graph)

- `lean-s7-cli`: read-only by default; writes, CPU start/stop and block deletion require
  `--allow-write`.
- `lean-s7-axioms` and `lean-s7-decode` (a decoder/encoder oracle for differential testing).

## Evidence added since 0.1.1

- Versioned, checksummed conformance corpus with a reproducible release archive
  (`corpus-v1-1.0.0`; corpus 1.0.1 only updates provenance for this version).
- Differential evidence against python-snap7 3.0.0 and 3.2.1 (467 cases, plus about 37,000
  fuzzed inputs) and the Wireshark S7comm dissector (232 probes). Ten python-snap7 issues
  found this way were fixed upstream.
- Replay of six public captures of real controllers (five S7-300, one other device):
  351 of 351 checks agree, including a PLC-driven download and a single-fragment upload;
  18 captured PDUs are always-on regression vectors.
- The integration suite runs on Windows (two Linux/macOS-only measurement steps are
  skipped there), and one timing-sensitive transport case has a generous deadline.

## Use

Use the pinned Lean 4.33.1 toolchain and `v0.2.0` as the Lake dependency revision. Python, Wireshark and native Snap7 remain test dependencies. No prebuilt binary
distribution is promised.

This is bounded evidence, not a full Client IO/scheduler-equivalence proof, and the
captures qualify only the conversations they contain. Physical controller and firmware
behavior beyond them, hard native socket cancellation (no runtime primitive exists),
exactly-once effects, multi-fragment uploads and industrial safety remain unqualified.
See `docs/RELEASE.md` and `docs/COMPLETENESS.md`.

The release attachment `validation-0.2.0.json` records the exact-commit main, tag and
resource-soak CI results (Linux and macOS) and the local validation checks.
