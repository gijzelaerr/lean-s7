# lean-s7 0.1.0

First experimental release of an independent Lean 4 classic S7comm client and
executable protocol specification. **Not PLC-qualified; do not use on production
equipment.** Python is used for testing, not required by the client at runtime.

## Included

- Bounded TPKT/COTP/S7 codecs, session negotiation and structured errors.
- PDU-aware scalar and multi-item memory access, typed DB values, STRING/WSTRING
  and serialized compound operations.
- Conservative reconnect/replay and detailed acknowledged/rejected/uncertain
  write progress, retaining caller/chunk provenance.
- SZL and typed information queries, clocks, CPU/password control, block
  discovery/metadata/upload/download and maintenance/process-image operations.
- Checked Lean contracts for selected actual codecs, planners, state machines
  and value boundaries; eight language-neutral conformance corpora.
- Corrected native block-info request layout, separate outer/subtype fields and
  full returned-number correlation. Typed metadata supports numbers 0–65535;
  the low-level five-digit request codec retains 0–99999.

## Evidence and use

The release candidate is checked with clean native builds/tests, the pinned
python-snap7 3.0.0 emulator, independently constructed fault peers, exact corpus
reproduction and a separate Lake consumer. Extended differential fuzzing covers
1,024 pure-model histories / 23,730 events; it is not a Client IO-equivalence
proof.

Independent endpoint tests use the unmodified official native Snap7 server at
revision `30f37da3114024a71ba93f7fd855c680b97a406f`. PDU240/480 profiles exercise
chunked DB/I/Q/M reads/writes, batching, typed strings/bits, recoverable rejection,
block metadata and CPU-state queries. A separate stdlib oracle checks all 9,728
registered backing bytes per profile. That endpoint does not qualify upload or
other unsupported native-server services. Native Snap7 is a test dependency,
not linked into lean-s7.

Use the pinned Lean 4.33.1 toolchain. A Lake consumer can pin this release:

```toml
[[require]]
name = "lean-s7"
git = "https://github.com/gijzelaerr/lean-s7.git"
rev = "v0.1.0"
```

Commit the consumer's generated `lake-manifest.json`. Build the native client
with `lake build lean-s7`; import `LeanS7` or `LeanS7.Client` for library use.
Public APIs are experimental and do not preserve the python-snap7 API. No
prebuilt binary distribution is promised; GitHub's source archives contain the
library, test harnesses and corpora.

## Explicit limits

- Classic S7comm only: no S7comm Plus or optimized symbolic access.
- No physical Siemens controller/firmware qualification, industrial safety
  certification or universal interoperability claim. Physical counter/timer
  indexing and controller-changing services need target-specific validation.
- Checked theorems cover stated boundaries, not the entire client, OS, scheduler,
  Python implementation or every remote service's semantics.
- Receive/connect deadlines are cooperative; socket sends and hard native
  cancellation remain outside the guarantee.
- Lost acknowledgements imply uncertain remote effects. Mutating retry opt-in
  can duplicate side effects; no exactly-once execution or rollback.
- Process-image overrides are not persistent CPU force-table entries. Compound
  calls are serialized on one client, not atomic against scans/other connections.
- STRING uses supported Latin-1; WSTRING uses UTF-16 within declared capacities.
  Clock values support 1990–2089; timezone/firmware interpretation is unqualified.
